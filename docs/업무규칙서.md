# 업무규칙서

이 문서는 검증 규칙 17개의 판단 기준과, 각 규칙에 걸리는 예와 걸리지 않는 예를 확정합니다. 코드(`src/recon/rules/`)와 테스트(`tests/test_rules_*.py`)가 이 문서를 기준으로 합니다. 설정값은 `config/rules.yaml`에 있습니다.

## 공통 처리 원칙

| 항목 | 기준 |
|---|---|
| 값 읽기 | 모든 값을 문자열로 읽고 앞뒤 공백(전각 공백 포함)을 지운다. 공백뿐인 값은 빈 값이다. 그 밖의 변환은 하지 않는다 |
| 숫자·날짜 | ASCII 숫자만 인정한다. 전각 숫자(０１２)는 형식 오류다. 파이썬 `int()`와 `\d`는 전각 숫자를 받아들이므로 따로 막는다 |
| 금액 | 정수만 인정한다. 천 단위 쉼표는 올바른 위치일 때만 허용한다(`1,000`은 정상, `1,00`은 오류). 계산은 정수(int)로만 한다 |
| 행번호 | 헤더를 1행으로 센 파일상의 위치다. 빈 줄은 건너뛰지만 번호는 유지하므로 엑셀로 열었을 때의 행번호와 같다 |
| 오류 키 | 거래내역은 `txn_id`, 비어 있으면 `행 N`이다. 집계표는 `account_no`, 비어 있으면 `행 N`이다 |
| 단계 | DQ → MD → SM → RC 순서로 진행한다. ERROR 행은 격리해 다음 단계에서 빼고, WARN 행은 통과시키되 검토대상에 올린다 |
| 단계 간 처리 | DQ ERROR 행은 MD 검사를 받지 않는다. 깨진 계좌번호가 MD-01을 중복으로 일으키지 않게 하기 위해서다. DQ·MD ERROR 행은 대사에서 뺀다 |
| 한 행의 오류 | 같은 단계 안에서는 한 행의 오류를 모두 기록한다. 단, 빈 값은 DQ-01만 기록하고 같은 칸에 형식 규칙을 겹쳐 기록하지 않는다 |
| 규칙 끄기 | `rules.yaml`에서 `false`로 둔 규칙은 실행하지 않는다. 그 결과 계산할 수 없는 값(예: 정수가 아닌 금액)은 이후 단계의 계산에서 빠진다 |

### 규칙이 아니라 실행 실패(FAILED)가 되는 경우

입력 파일을 믿고 검증할 수 없는 경우입니다. 실행 이력에 원인을 남기고 바로 멈춥니다.

- 파일 누락, 빈 파일, 헤더만 있는 파일
- 지원하지 않는 형식 (csv, xlsx만 가능), 인코딩 판별 실패 (UTF-8, CP949만 가능)
- 필수 컬럼 누락, 컬럼명 중복
- 컬럼 수가 헤더와 다른 행. 예를 들어 `1,000`을 따옴표 없이 저장해 컬럼이 밀린 경우다
- 기준정보 파일 오류: 계좌번호·거래코드 중복 또는 빈 값, status·direction·active_yn 값 오류, 날짜 형식 오류, CLOSED 계좌에 해지일 없음

데이터 오류가 많은 것은 FAILED가 아니라 SUCCESS입니다.

## ① 품질 검증 (DQ) — 거래내역

| ID | 규칙 | 판단 기준 | 걸리는 예 | 걸리지 않는 예 | 심각도 |
|---|---|---|---|---|---|
| DQ-01 | 필수값 누락 | `txn_id, txn_dt, account_no, txn_code, direction, amount` 중 빈 값 (공백뿐인 값 포함). 빈 칸마다 1건 | amount=``, txn_id=`   ` | channel=`` (선택 컬럼), amount=` 5000 ` | ERROR |
| DQ-02 | 계좌번호 형식 | `^\d{3}-\d{2}-\d{6}$` (ASCII) 불일치 | `12345678901`, `1234567890` (엑셀이 숫자로 바꿔 앞자리 0 손실), `123-45-67890`, `１２３-45-678901` | `012-34-567890`, `123-45-678901` | ERROR |
| DQ-03 | 거래일시 형식·범위 | `YYYY-MM-DD HH:MM:SS`와 정확히 일치하지 않음 (0 채움 필수), 또는 날짜가 기준일과 다름 | `2026-10-14 23:59:59`, `2026/10/15 10:00:00`, `2026-10-15 9:00:00` | `2026-10-15 00:00:00`, `2026-10-15 23:59:59` | ERROR |
| DQ-04 | 금액 형식 | 정수가 아니거나 0 이하 | `0`, `-1000`, `1000.5`, `3.0`, `１０００`, `1,00` | `1`, `1,000`, `1500000000` | ERROR |
| DQ-05 | 입출금 구분 값 | `D`, `W` 이외의 값 (대소문자 구분) | `X`, `d`, `입금` | `D`, `W` | ERROR |
| DQ-06 | 거래번호 중복 | 같은 txn_id가 2건 이상. 8개 컬럼 값이 모두 같으면 첫 행만 남기고 나머지를 격리한다. 하나라도 다르면 전부 격리한다. 빈 txn_id는 묶지 않는다 | 같은 행이 두 번 (뒤 행만 기록), 같은 txn_id에 금액만 다름 (두 행 모두 기록) | txn_id가 모두 다름 | ERROR |
| DQ-07 | 의심 중복 | txn_id는 다르나 계좌·일시·코드·금액(숫자 값)이 모두 같음. DQ ERROR 행은 비교하지 않는다. 먼저 나온 행이 기준이고 뒤 행만 기록하며, 두 행 모두 대사에 포함한다 | txn_id만 바꾼 복제 행, `10000`과 `10,000` | 금액이나 시각이 1이라도 다름 | WARN |

내용 비교는 문자열 기준입니다. `1,000`과 `1000`은 DQ-06에서는 다른 내용입니다(전부 격리). DQ-07에서는 같은 금액으로 봅니다.

## ② 기준정보 정합성 (MD) — 거래내역 × 마스터

DQ ERROR가 없는 행만 검사합니다.

| ID | 규칙 | 판단 기준 | 걸리는 예 | 걸리지 않는 예 | 심각도 |
|---|---|---|---|---|---|
| MD-01 | 미등록 계좌 | 계좌 마스터에 없는 account_no | `999-99-999999` | 마스터에 있는 계좌 | ERROR |
| MD-02 | 계좌 유효기간 외 거래 | 거래일 < open_date이면 "개설일 이전", status가 CLOSED이고 거래일 > close_date이면 "해지일 이후" | 해지일 다음날 거래, 개설일 전날 거래 | 해지일 당일, 개설일 당일 거래 | ERROR |
| MD-03 | 미등록·폐지 거래코드 | 코드 마스터에 없거나 active_yn = N | `X01`, 폐지 코드 `W06` | 사용 중인 코드 | ERROR |
| MD-04 | 코드-방향 불일치 | 코드가 마스터에 있을 때 거래의 direction ≠ 코드의 direction. 폐지 코드도 비교하며 MD-03과 함께 기록한다. 마스터에 없는 코드는 비교하지 않는다 | 입금 코드 `D01`에 `W` | `D01`+`D`, `W01`+`W` | ERROR |
| MD-05 | 지급정지 계좌 출금 | status = SUSPENDED이고 direction = W | 지급정지 계좌의 출금 | 지급정지 계좌의 입금, 정상 계좌의 출금 | WARN |

## ③ 집계표 검증·거래-집계 대사 (SM·RC)

**집계 대상 계좌**는 기준일에 유효한 계좌 전부입니다. 즉 open_date ≤ 기준일이고, close_date가 비어 있거나 기준일 이후(당일 포함)인 계좌입니다. 거래가 0건이어도 집계표에 0으로 1행이 있어야 합니다.

| ID | 규칙 | 판단 기준 | 걸리는 예 | 걸리지 않는 예 | 심각도 |
|---|---|---|---|---|---|
| SM-01 | 집계표 자체 오류 | 계좌 중복 행, base_date ≠ 기준일, 건수·입출금 금액이 정수가 아니거나 음수, 기초·기말잔액이 정수가 아님, account_no 빈 값. 계좌당 1건만 기록하고 사유는 모두 메시지에 적는다. 해당 계좌는 RC-01~04에서 빼고 대사결과에 "집계표 오류로 대사 제외"로 표시한다 | 같은 계좌 2행, base_date `2026-10-14`, deposit_count `-1` | 기초잔액 `-5000` (마이너스 통장 허용), 금액 `7,000` | ERROR |
| RC-01 | 계좌 존재 불일치 | 집계 대상 계좌가 집계표에 없음 (거래 유무와 무관). 또는 집계표에 있으나 집계 대상이 아님 (마스터에 없거나 기준일에 유효하지 않음). SM-01 제외 계좌는 검사하지 않고, RC-01 계좌는 RC-02~04를 검사하지 않는다 | 거래 0건 계좌의 행 삭제, 마스터에 없는 계좌 행 추가 | 거래 0건 계좌가 0으로 있음 | ERROR |
| RC-02 | 입금 불일치 | 정상 거래(ERROR 제외, WARN 포함)의 계좌별 입금 건수 ≠ 집계표, 또는 금액 차이 > 허용오차 | 입금 건수 +1, 입금 금액 +1,000 | 일치, 허용오차 이내 | ERROR |
| RC-03 | 출금 불일치 | 출금에 대해 RC-02와 같은 기준 | 출금 건수 −1 | 일치 | ERROR |
| RC-04 | 잔액 등식 불일치 | 집계표의 기초 + 입금 − 출금 ≠ 기말 (차이 > 허용오차). 집계표 자체 검증이다 | 기말잔액 +1,000, 입금 금액만 바꾸고 기말은 그대로 | 건수만 바뀜 | ERROR |

허용오차는 `rules.yaml`의 `tolerance.amount`이며 기본값은 0원(완전 일치)입니다. 건수는 항상 완전 일치여야 합니다.

### 대사 차이 원인 표시

차이가 난 계좌의 대사결과에 원인을 아래 순서로 판정해 하나를 붙입니다. 잔액 등식이 깨진 경우에는 그 표시를 함께 붙입니다.

1. **제외 거래 있음:** 이 계좌에 격리된(ERROR) 거래가 있음
2. **검토 거래 있음:** 격리 거래는 없고 WARN 거래(의심 중복, 지급정지 출금)가 있음
3. **원인 미상:** 위 둘 다 없음
4. **잔액 등식 불일치:** RC-04가 걸림 (1~3과 함께 표시될 수 있음)

계좌번호가 깨졌거나 마스터에 없어 어느 계좌에도 연결할 수 없는 격리 행은, 보고서 요약의 "계좌 미식별 격리 N건"으로 따로 셉니다.
