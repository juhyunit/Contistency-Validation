# 데이터사전

## 입력 파일 (4개, 기준일 하루치)

인코딩은 UTF-8(BOM 포함 가능)과 CP949를 받습니다. 어느 쪽으로 읽었는지 `input_files.encoding`에 기록합니다. 형식은 확장자로 판단합니다: `.csv`, `.xlsx`, `.xlsm`. 모든 값은 문자열로 읽습니다.

### ① transactions.csv — 거래내역

| 컬럼 | 타입 | 필수 | 설명 | 예 |
|---|---|---|---|---|
| txn_id | 문자열 | Y | 거래 고유번호 | `T20261015000001` |
| txn_dt | 일시 | Y | `YYYY-MM-DD HH:MM:SS` | `2026-10-15 09:30:00` |
| account_no | 문자열 | Y | 계좌번호 `123-45-678901` (앞자리 0 유지) | `012-34-567890` |
| txn_code | 문자열 | Y | 거래코드 (거래코드 마스터 참조) | `D01` |
| direction | 문자열 | Y | `D`(입금) / `W`(출금) | `D` |
| amount | 정수 | Y | 원 단위, 0보다 큼, 천 단위 쉼표 허용 | `150000`, `"1,500,000"` |
| channel | 문자열 | N | `BRANCH` / `ATM` / `MOBILE` / `INTERNET` | `ATM` |
| branch_code | 문자열 | N | 처리 영업점 코드 4자리 | `0012` |

- **선택 컬럼:** channel, branch_code는 컬럼이 아예 없어도 됩니다(빈 값으로 채움).
- **추가 컬럼:** 위에 없는 컬럼이 있어도 무시하고 진행합니다.

### ② account_summary.xlsx — 계좌별 일일 집계

첫 번째 시트를 읽습니다. 날짜 셀은 `YYYY-MM-DD`로, 정수형 실수 셀(`1000.0`)은 `1000`으로 바꿔 읽습니다.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| base_date | 날짜 | 기준일 |
| account_no | 문자열 | 계좌번호 |
| opening_balance | 정수 | 기초잔액 (음수 허용) |
| deposit_count / deposit_amount | 정수 | 입금 건수 / 금액 (0 이상) |
| withdrawal_count / withdrawal_amount | 정수 | 출금 건수 / 금액 (0 이상) |
| closing_balance | 정수 | 기말잔액 (음수 허용) |

**집계 대상 계좌**는 기준일에 유효한 계좌 전부입니다(open_date ≤ 기준일 ≤ close_date, 해지일이 없으면 계속 유효). 거래가 0건이어도 0으로 1행을 둡니다.

### ③ account_master.csv — 계좌 마스터

| 컬럼 | 설명 |
|---|---|
| account_no | 계좌번호 (기본키, 중복 불가) |
| product_code | 상품코드 |
| status | `ACTIVE` / `CLOSED` / `SUSPENDED` |
| open_date / close_date | 개설일 / 해지일 `YYYY-MM-DD`. 해지 전이면 close_date는 빈 값이고, CLOSED이면 필수다 |

### ④ txn_code_master.csv — 거래코드 마스터

| 컬럼 | 설명 |
|---|---|
| txn_code | 거래코드 (기본키, 중복 불가) |
| txn_name | 거래명 (예: 현금입금, 계좌이체출금) |
| direction | 이 코드가 허용하는 방향 `D` / `W` |
| active_yn | 사용 여부 `Y` / `N` |

마스터 파일 값이 규칙에 맞지 않으면 거래를 판정할 기준이 없으므로 실행이 FAILED가 됩니다.

## 출력 파일 (`data/output/run_{run_id}/`)

### report_{run_id}.xlsx

| 시트 | 내용 |
|---|---|
| 요약 | 실행 번호, 기준일, 건수(총·정상·격리·검토), 오류 수, 대사 일치·불일치·제외·존재 불일치 계좌 수, 계좌 미식별 격리 건수, 경고 / 입력 파일별 파일명·인코딩·행 수·SHA-256 / 규칙별 오류 건수 (17개 전부) |
| 오류목록 | 규칙, 심각도, 파일, 원본 행번호, 키, 컬럼, 값, 메시지 |
| 대사결과 | 아래 recon_results 컬럼 (한글 헤더) |
| 검토대상 | WARN 오류만 (오류목록과 같은 컬럼) |

값이 `=`로 시작해도 엑셀 수식으로 실행되지 않도록 문자열로 저장합니다.

### CSV (UTF-8 BOM)

| 파일 | 컬럼 |
|---|---|
| clean_transactions.csv | row_no + 거래내역 8개 컬럼. ERROR가 없는 거래이며, WARN 거래도 포함한다 |
| quarantine_transactions.csv | row_no + 거래내역 8개 컬럼 + error_rules (규칙 ID 목록) + error_messages |

### run.log

단계별 시작·종료와 ERROR·WARN 건수, 입력 파일 정보, 경고, 최종 상태를 기록합니다.

## DB 테이블

DB 주소는 `DATABASE_URL` 환경변수로 정하며, 기본값은 `data/recon.db`(SQLite)입니다. 테이블은 첫 실행 때 자동으로 만들어집니다.

| 테이블 | 컬럼 | 용도 |
|---|---|---|
| runs | run_id, parent_run_id, base_date, status, started_at, finished_at, error_message, warning_message, output_dir, stats_json | 실행 1회 = 1행 |
| input_files | run_id, file_type, file_name, sha256, encoding, row_count, archive_path, duplicate_of_run_id | 입력 원본 추적 |
| issues | run_id, rule_id, severity, file_type, row_no, record_key, column_name, value, message | 오류 1건 = 1행 |
| recon_results | run_id, account_no, result, diff_cause, summary_row_no, is_target, in_summary, 항목별 거래값·집계값·차이 (입금·출금 건수·금액), opening_balance, closing_balance, expected_closing_balance, balance_diff, deposit/withdrawal/balance_mismatch | 계좌별 대사 결과 |
| rule_stats | run_id, rule_id, hit_count | 규칙별 건수 (추이 확인용) |

- **runs.status:** `PENDING → RUNNING → SUCCESS / FAILED`. 다음 실행이 시작될 때 `rules.yaml`의 `stale_running_minutes`(기본 60분)보다 오래 RUNNING·PENDING인 실행은 FAILED로 정리됩니다.
- **result 값:** `일치` / `불일치` / `집계표 오류로 대사 제외` / `계좌 존재 불일치`
- **diff_cause 값:** `제외 거래 있음` / `검토 거래 있음` / `원인 미상` / `잔액 등식 불일치` (여럿이면 ` / `로 연결)

## 합성 데이터와 정답 파일 (`tools/generate_data.py`)

| 경로 | 내용 |
|---|---|
| `data/sample/clean/` | 깨끗한 데이터. 검증하면 오류 0건, 모든 계좌 일치 |
| `data/sample/injected/` | 오류 81건을 심은 데이터 + `injected_errors.csv` |

`injected_errors.csv` 컬럼:

| 컬럼 | 설명 |
|---|---|
| error_id | 주입 오류 번호. 같은 txn_id에 다른 내용을 심은 DQ-06은 두 행이 같은 번호를 쓴다 |
| expected_rule | 기대 규칙 (한 행에 1개) |
| file | `transactions.csv` 또는 `account_summary.xlsx` |
| row_no | 오류를 심은 후 파일 기준 행번호. 집계표에서 삭제된 행은 빈 값 |
| record_key | txn_id (없으면 `행 N`) 또는 계좌번호 |
| original_account_no | 오류를 심기 전의 계좌번호 (연쇄 대사 차이 분류용) |
| detail | 무엇을 바꿨는지. 집계표 변조는 `deposit_amount +50000`처럼 컬럼과 변화량을 적고, 평가 때 금액·건수 변조를 구분하는 데 쓴다 |

**매칭 기준**은 거래내역 오류는 (file, row_no, expected_rule), 집계표 오류는 (file, record_key, expected_rule)입니다.
